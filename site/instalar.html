Instalar

No servidor onde corre o CrowdSec, como root. Funciona em Debian, Ubuntu, RHEL e derivados, e openSUSE, em amd64 ou arm64, com systemd.

curl -fsSL https://sentinela.nozaf.ao/instalar.sh | sudo bash

O que o instalador faz

  1. Encontra o CrowdSecInstalado por pacotes no próprio servidor, ou num contentor crowdsecurity/crowdsec. Se não houver, pergunta antes de o instalar a partir do repositório oficial do CrowdSec. Diz também se há Docker; não é preciso quando o CrowdSec corre no servidor.
  2. Descarrega e verifica a versãoDo GitHub, para a sua arquitectura. O ficheiro SHA256SUMS tem de ter uma assinatura OpenPGP válida da chave do projecto, e cada ficheiro tem de corresponder ao seu SHA256. Se alguma verificação falhar, não instala nada.
  3. Prepara o sistemaCria o utilizador sentinela, regista uma máquina na API local (a palavra-passe vai directamente para um ficheiro e nunca aparece no ecrã) e uma regra de sudo que só permite cscli e systemctl reload crowdsec.
  4. Escolhe onde escutarPor omissão em 127.0.0.1:8095. Se encontrar uma VPN (WireGuard, Tailscale) oferece o endereço dela. Um endereço público é recusado, a não ser que o peça explicitamente.
  5. Cria a primeira contaPede a palavra-passe sem a mostrar e configura o TOTP, com QR code quando há qrencode.
  6. Arranca e confirmaActiva o serviço sentinela e verifica que responde.

Pode corrê-lo de novo quando quiser: repara o que faltar e mantém as contas e a configuração.

Ler antes de correr

Correr um script da Internet como root pede confiança. Se preferir, descarregue-o, leia-o e só depois corra:

curl -fsSLO https://github.com/Noz-AF-Angola/sentinela/releases/latest/download/instalar.sh
less instalar.sh
sudo bash instalar.sh

Para verificar a assinatura dos ficheiros de uma versão à mão:

curl -fsSL https://sentinela.nozaf.ao/chave.asc | gpg --import
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum -c --ignore-missing SHA256SUMS

Depois de instalar

O instalador fica no servidor como sentinela-admin:

sudo sentinela-admin update              # última versão, com as mesmas verificações
sudo sentinela-admin user ana viewer     # nova conta, ou nova palavra-passe e TOTP
sudo sentinela-admin status
sudo sentinela-admin uninstall           # SENTINELA_PURGE=1 apaga também /etc/sentinela

Se escuta em 127.0.0.1, abra-a por um túnel SSH a partir do seu computador:

ssh -N -L 8095:127.0.0.1:8095 utilizador@servidor
# e depois http://localhost:8095

Opções

São variáveis de ambiente. Com curl | sudo bash, ponha-as depois do sudo, por exemplo curl -fsSL … | sudo SENTINELA_TELEMETRIA=0 bash.

SENTINELA_VERSION
versão a instalar; por omissão a mais recente
SENTINELA_LISTEN
endereço da interface, por exemplo 10.0.0.1:8095
SENTINELA_YES=1
instala dependências em falta sem perguntar (nunca responde à telemetria)
SENTINELA_TELEMETRIA=0
não pergunta nem envia a contagem anónima
SENTINELA_FROM
instala a partir de uma pasta com os ficheiros da versão, para servidores sem Internet
SENTINELA_PURGE=1
com uninstall, apaga também as contas

Telemetria

No fim de uma instalação feita num terminal, o instalador pergunta se pode enviar uma mensagem anónima, para o projecto saber quantos servidores o usam. A resposta por omissão é não. Sem terminal, ou com SENTINELA_TELEMETRIA=0, não pergunta nem envia nada. A interface web nunca envia nada.

A mensagem inteira é esta, enviada para https://apoio.nozaf.ao/v1/instalacoes:

{"id":"0b5c6e1e-3c1f-4a52-9d9e-2f8a7b1c4d00","projecto":"sentinela","versao":"0.2.0","so":"ubuntu-24.04","arq":"amd64","evento":"instalar"}

O id é um UUID aleatório criado no seu servidor quando aceita, guardado em /etc/sentinela/id. Não leva endereço IP, nome da máquina, domínio nem configuração, e o serviço que a recebe não guarda o IP. Para deixar de enviar: echo nao | sudo tee /etc/sentinela/telemetria.
